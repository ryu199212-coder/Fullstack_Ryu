# 1. ERD
- ERD
- ENTITY(테이블)
- RELATIONSHIP(관계)
- ATTRIBUTE(속성)
예) EMP(deptno : 부서번호, FK) - DEPT(deptno : 부서번호, PK)
> 데이터간 **관계**에 초점을 둔 모델

# 2. 정규화(NF : Normal Form)
- 이상을 제거
- 이상이란? 공간낭비, 삽입, 갱신, 삭제
- 1NF ~ 5NF

# 3. 1NF(원자값)
- 원자값, 더이상 쪼갤 수 없는 단위
1) 각 속성은 하나의 값만 갖는다

예)
[BEFORE]
|STD_ID |  ENAME  | SAL |
|-------|---------|-----|
|1111   |  SALLY  | A,A+|

[AFTER]
|STD_ID |  ENAME  | SAL |
|-------|---------|-----|
|1111   |  SALLY  |  A+ |
|1111   |  SALLY  |  A  |

# 4. 2NF(부분함수 종속제거)
- 종속관계 : ~를 알면 ~를 알 수 있다
            x=결정자  y=종속자
 > 모든 속성이 기본키에 완전함수 종속되면 제 2정규형
 > 종속자가 기본키에만 종속
예)

         x=결정자    →   y=종속자
1-1. <학번, 수강과목> → 성적

1-3. {학번}          → professor

1-2 ~ 1-4
- 부분함수 종속
: 기본키가 복합키(학번, 수간과목)
: 종속자가 기본키를 구성하는 속성중 일부에게만 종속된 경우

# 5. 3NF(이행함수 종속제거)
1. x → Y → Z
2. 다른 후보키에 의존하지 않음
3. 테스트시 insert, update, delete 이상 확인

예) <학번:PK>을 알면 <지도교수:후보키>를 알고
                   <지도교수:후보키>를 알면 <학부>를 알 수 있다.

[학번(PK), 지도교수], [지도교수(PK), 학부]

※KEY
1. KEYT? 튜플, 행, 레코드(1, 홍길동, 10) 들을 구분 할 수 있는 기준필드(열, attribute)
2. 종류 : 후보키, 기본키, 대체키, 슈퍼키(복합키), 외래키
3. 후보키 : 기본키로 사용 할 수 있는 속성(주민증, 학생증, 사원증)
        유일성 + 최소성
4. 기본키 : 선택된 주 키(primary key), 중복된 값x / null x
5. 대체키 : 선택 안된 키
6. 슈퍼키(복합키) : 속성 + 속성 구성된 키
        유일성(구분) + 최소성 x
7. 외래키 - 테이블(entity) 와 테이블 연결 속성

# 6. 4NF(가치 종속 제거)
- 프로그래밍 과목
- 담당교수2, 교재코드2

[BEFORE]
<과목, 교수코드, 교재코드>
2*2 = 4
2*3 = 6

[AFTER]
<과목, 교수코드> 2
<과목, 교재코드> 2

# 7. 5NF(join종속 제거)
- 하나의 테이블을 여러개의 테이블로 분해 했다가 다시 조인했을 때 데이터 손실은 없지만,
필요없는 데이터가 생심

예) 다:다 관계 > 중간테이블 생성(많이 쓰는 필드를 빼서)
교수는 여러개의 교재를 갖는다
교재는 여러명의 교수가 사용 할 수 있다
[BEFORE]
<교수> -------------------------- <교재>

[AFTER]
<교수> --------<교수교재>--------- <교재>
